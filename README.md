# Fragrance — интернет-магазин индивидуальной парфюмерии

Fragrance — учебное веб-приложение, в котором покупатель собирает собственный аромат из готовой основы и подходящей акцентной ноты, выбирает флакон, придумывает название и оформляет заказ. Магазин помогает подобрать парфюм через понятные образы и настроение: сосновый лес, морское побережье, вечер у камина или кофейня.

Проект рассчитан на небольшой парфюмерный магазин. Покупатель получает простой конструктор и личный кабинет, а администратор — средства управления ассортиментом и обработки заказов.

> Проект находится в разработке. Реализованы каталог, конструктор, регистрация и вход, профиль покупателя, корзина, оформление заказа, история и отмена нового заказа, административное управление каталогом и заказами. Повтор заказа, аналитика, импорт и отчёты пока запланированы. Ниже описан целевой функционал приложения.

## Что уже можно попробовать

Выберите атмосферу, добавьте одну из подходящих нот, укажите объём и форму флакона, затем дайте аромату имя. Приложение покажет состав и рассчитанную стоимость в белорусских рублях (BYN). Доступны классические и гранёные флаконы объёмом 30, 50 и 100 мл; цены пока демонстрационные.

Черновик сохраняется на этом устройстве и восстанавливается при повторном открытии конструктора. Сейчас хранится одна последняя сохранённая композиция. Сохранение черновика не оформляет заказ.

Кнопка «Добавить в корзину» предложит гостю войти или зарегистрироваться, сохранив его выбор. После входа можно добавить композицию, изменить количество флаконов и подтвердить заказ с именем и телефоном получателя. В личном кабинете доступны изменение профиля, список заказов, их состав и отмена заказа со статусом «Новый».

В корзине допускается до 20 композиций и до 20 флаконов каждой. При изменении цен приложение просит проверить новую сумму перед повторным подтверждением. Повторная отправка одного подтверждения не создаёт дубликат заказа.

Администратору доступна отдельная панель: добавление и редактирование атмосфер, нот и флаконов, настройка совместимости, поиск, сортировка и скрытие товаров. Изображение выбирается из готовой коллекции. Заказы можно искать по номеру, периоду и статусу, открывать их состав, принимать в работу, завершать или отменять. Права администратора назначаются владельцем приложения и недоступны при обычной регистрации.

## Идея проекта

Основой выбора служит **атмосфера** — готовая композиция с описанием характера и основных нот. Покупателю не нужно знать парфюмерные пропорции: он выбирает понравившееся настроение и дополняет его одной совместимой нотой.

Например, к атмосфере «Утро в сосновом лесу» можно добавить мяту для ощущения свежести или розовый перец для пряного оттенка. После этого покупатель выбирает доступный объём, форму флакона и название своего аромата.

Совместимые сочетания заранее задаёт администратор. Конструктор работает с ограниченным набором готовых вариантов и не требует расчёта химических формул или произвольного смешивания ингредиентов.

## Как оформляется заказ

1. **Выбор атмосферы.** Покупатель просматривает карточки с изображением, описанием и основными нотами аромата.
2. **Выбор акцента.** Приложение показывает только ноты, подходящие к выбранной основе, и кратко объясняет их характер.
3. **Выбор флакона.** Покупатель выбирает форму и один из доступных объёмов, например 30, 50 или 100 мл. Стоимость обновляется при изменении выбора.
4. **Название аромата.** Покупатель вводит собственное название и проверяет итоговую карточку композиции.
5. **Корзина.** Можно добавить несколько ароматов, изменить количество флаконов или удалить ненужные позиции.
6. **Подтверждение.** После входа в аккаунт покупатель указывает имя, телефон и при необходимости комментарий. Приложение сохраняет заказ и показывает его номер и сумму.
7. **Получение.** Покупатель следит за статусом в личном кабинете. Для учебного сценария предусмотрен самовывоз, без интеграции с доставкой и онлайн-оплатой.

При возвращении на предыдущий шаг выбранные параметры сохраняются. Если покупатель меняет атмосферу, несовместимая акцентная нота сбрасывается и предлагается новый выбор.

## Возможности покупателя

### Каталог и конструктор

- Просмотр атмосфер, их описаний и базовых нот.
- Поиск по названию и описанию, сортировка атмосфер по названию.
- Пошаговая сборка аромата с подсказками для каждого варианта.
- Просмотр состава, объёма, флакона и стоимости перед добавлением в корзину.
- Собственное название для каждой композиции.

Просматривать каталог и пользоваться конструктором можно без регистрации. Для сохранения корзины и оформления заказа нужен аккаунт; текущая композиция сохраняется при переходе ко входу.

### Личный кабинет и заказы

- Регистрация по имени, email и паролю, вход и выход из аккаунта.
- Просмотр и изменение имени и телефона.
- Корзина с количеством позиций и общей стоимостью.
- История заказов с датой, составом, суммой и текущим статусом.
- Отмена своего заказа, пока администратор не взял его в работу.
- Повтор заказа: добавление прежних композиций в корзину по актуальным ценам. Если компонент больше недоступен, приложение предлагает изменить выбор.

Отмена нового заказа и повторное добавление любимого аромата делают магазин удобнее и используют уже существующие данные без сложных дополнительных подсистем.

## Возможности администратора

### Управление ассортиментом

Администратор добавляет и редактирует атмосферы, акцентные ноты и варианты флаконов. Для атмосферы задаются название, описание, изображение, базовые ноты и стоимость основы; для акцента — описание и доплата; для флакона — форма, объём и цена.

Администратор определяет, какие акценты доступны для каждой атмосферы. В справочниках предусмотрены поиск, сортировка и возможность временно скрыть позицию из продажи. Неиспользуемую позицию можно удалить, а участвующую в заказах — только скрыть, чтобы сохранить историю.

### Обработка заказов

В общем списке можно найти заказ по номеру, отфильтровать заказы по периоду или статусу и открыть подробности: покупателя, контакты, комментарий, композиции, количество и сумму.

Предусмотрены четыре статуса:

| Статус | Значение |
| --- | --- |
| Новый | Заказ оформлен и ожидает обработки |
| В работе | Администратор принял заказ и готовит его к выдаче |
| Завершён | Заказ выдан покупателю |
| Отменён | Выполнение заказа прекращено |

Обычный порядок обработки: «Новый» → «В работе» → «Завершён». Администратор может отменить новый заказ или заказ в работе. Покупатель может отменить только свой новый заказ. Завершённые и отменённые заказы остаются в истории и больше не редактируются.

### Простая статистика

За выбранный период администратор видит количество оформленных заказов, распределение по статусам, сумму завершённых заказов и самые популярные атмосферы по количеству заказанных флаконов в завершённых заказах. Период определяется датой оформления заказа; отменённые заказы не включаются в сумму и рейтинг.

Для курсового проекта достаточно таблицы показателей и выгрузки отчёта в Excel. Дополнительно предусматривается импорт и экспорт каталога в JSON с проверкой обязательных полей, совместимости и дубликатов. Персональные данные покупателей в обмен каталога не входят.

## Основные правила работы

- В одной композиции выбираются одна атмосфера, одна совместимая нота и один вариант флакона. Разные композиции оформляются отдельными позициями корзины.
- Цена одного флакона рассчитывается как стоимость основы и акцента за выбранный объём плюс стоимость самого флакона. Итог заказа учитывает количество каждой позиции.
- Окончательную стоимость рассчитывает сервер по актуальным ценам. Если цена изменилась после добавления в корзину, покупатель видит обновлённую сумму до подтверждения.
- При оформлении сохраняются названия компонентов, параметры флакона и цена на момент покупки. Изменение каталога не меняет ранее оформленные заказы.
- Недоступные компоненты нельзя заказать. Перед оформлением приложение повторно проверяет все позиции корзины.
- Заказ и его позиции сохраняются одной операцией: при ошибке не должно появляться частично оформленного заказа или пропадать содержимое корзины.
- Покупатель имеет доступ только к собственным данным и заказам. Управление ассортиментом и всеми заказами доступно только администратору.

## Данные приложения

База данных хранит восемь основных связанных сущностей:

| Сущность | Какие данные хранит |
| --- | --- |
| Пользователи | Имя, email, телефон, хеш пароля и роль |
| Атмосферы | Название, описание, изображение, базовые ноты, цена основы и доступность |
| Акцентные ноты | Название, категория, описание, доплата и доступность |
| Совместимость | Допустимые сочетания атмосфер и акцентов |
| Варианты флаконов | Форма, объём, цена и доступность |
| Позиции корзины | Покупатель, выбранная композиция, собственное название и количество |
| Заказы | Покупатель, дата, контакты, комментарий, статус и итоговая сумма |
| Позиции заказа | Состав каждой композиции, название, объём, флакон, количество и зафиксированная цена |

Одна атмосфера может сочетаться с несколькими акцентами, а один акцент — подходить нескольким атмосферам. Один пользователь может оформить несколько заказов, каждый из которых содержит одну или несколько позиций.

## Технологии

| Часть приложения | Технологии |
| --- | --- |
| Интерфейс | HTML, CSS, JavaScript |
| Сервер | Node.js и Express |
| База данных | MySQL |
| Доступ к данным | SQL-запросы через mysql2, без ORM |
| Взаимодействие клиента и сервера | REST API и JSON |

Приложение состоит из одного сервера, веб-интерфейса и одной базы данных. Интерфейс адаптируется к компьютерам и телефонам. Для защиты данных используются хеширование паролей, серверная проверка прав и вводимых значений, параметризованные запросы и сессии пользователей.

## Границы проекта

Основной результат — небольшой законченный магазин: выбор аромата, корзина, заказ, личный кабинет и административная панель. Простая статистика, обмен каталогом и один вид отчёта дополняют работу с базой данных.

Онлайн-оплата, автоматические рассылки, доставка, промокоды, несколько валют, многоязычность, учёт парфюмерного сырья и профессиональное составление рецептур в объём проекта не входят. Их отсутствие позволяет сосредоточиться на качественной реализации основного сценария.

## Порядок разработки

1. Завершить конструктор: выбор акцента, объёма, флакона и названия, расчёт стоимости.
2. Добавить регистрацию, вход, корзину и сохранение заказа.
3. Реализовать личный кабинет, историю, отмену и повтор заказа.
4. Добавить административное управление каталогом и заказами.
5. Реализовать статистику, обмен каталогом и отчёт.
6. Проверить полный путь покупателя и администратора, ошибки ввода, ограничения доступа и сохранность данных.

Готовое приложение должно позволять покупателю самостоятельно собрать аромат и оформить заказ, а администратору — обработать его, обновить ассортимент и получить понятную сводку по работе магазина.
