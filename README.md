# Fragrance — магазин индивидуальной парфюмерии

Fragrance — учебный веб-магазин, в котором покупатель собирает аромат из готовой атмосферы и совместимой акцентной ноты, выбирает флакон и придумывает название. Примеры атмосфер: сосновый лес, морское побережье, вечер у камина и кофейня.

Проект рассчитан на небольшой магазин с самовывозом. Конструктор использует готовые сочетания, заданные администратором, и не рассчитывает химические рецептуры. Сложность соответствует курсовому проекту: один сервер, одна MySQL и обычные веб-страницы.

## Что реализовано

### Покупатель

- Каталог атмосфер с описанием, изображениями, поиском и сортировкой.
- Конструктор: атмосфера → совместимая нота → флакон и объём → собственное название.
- Расчёт стоимости сервером в белорусских рублях (BYN).
- Сохранение последнего черновика на устройстве и восстановление после входа.
- Регистрация, вход, выход, изменение имени и телефона.
- Корзина, изменение количества и удаление позиций.
- Оформление заказа с контактами и комментарием, история и просмотр состава.
- Отмена собственного нового заказа, повтор композиций в корзину по актуальным ценам и просмотр истории статусов.

Просмотр каталога и расчёт доступны гостю. Для корзины и оформления нужен аккаунт. В корзине допускается до 20 композиций и до 20 флаконов каждой.

### Администратор

- Добавление и редактирование атмосфер, нот и флаконов.
- Выбор изображения из готовой коллекции.
- Настройка совместимости атмосфер и нот.
- Поиск, сортировка, постраничный просмотр, скрытие и восстановление доступности позиций.
- Удаление позиций, которые не используются в корзинах и заказах.
- Поиск заказов по номеру, периоду и статусу, просмотр контактов и состава.
- Принятие заказа в работу, завершение или отмена.
- Статистика за период: количество заказов, распределение по статусам, сумма завершённых заказов и 10 популярных атмосфер.
- Выгрузка табличного отчёта CSV для Excel и обмен каталогом в JSON.

Роль администратора назначается локальной командой владельцем приложения. Обычная регистрация создаёт покупателя.

## Заказы и стоимость

Цена флакона = (цена основы за мл + цена акцента за мл) × объём + стоимость флакона. Сумма заказа учитывает количество. Цены демонстрационные и редактируются администратором.

Сервер повторно проверяет наличие, доступность и совместимость компонентов. При изменении цены покупатель подтверждает обновлённую корзину. Повторная отправка одного подтверждения не создаёт второй заказ.

| Статус | Действия |
| --- | --- |
| Новый | Администратор принимает в работу или отменяет; владелец может отменить |
| В работе | Администратор завершает или отменяет |
| Завершён | Сохраняется в истории без дальнейшей смены статуса |
| Отменён | Сохраняется в истории без дальнейшей смены статуса |

Названия компонентов, объём и цена копируются в позиции заказа при оформлении. Изменения каталога не переписывают прошлые покупки. Создание заказа, его позиций, первого события истории и очистка корзины выполняются одной транзакцией.

Изменения статуса сохраняются в журнале с автором и временем. Журнал отображается в подробностях заказа у покупателя и администратора. Для заказов, созданных до появления журнала, сохраняется только достоверный текущий статус с отметкой переноса.

## Хранение данных

Схема содержит **15 таблиц: 13 предметных и 2 служебные**.

| Таблица | Назначение |
| --- | --- |
| roles | Роли покупателей и администраторов |
| users | Аккаунты, контакты, хеши паролей и роль |
| accent_categories | Единый справочник категорий акцентных нот |
| atmospheres | Основы ароматов, базовые ноты, цены и доступность |
| accents | Акцентные ноты, категория, цена и доступность |
| atmosphere_accents | Допустимые сочетания основ и акцентов |
| bottles | Варианты флаконов: форма, объём, цена |
| cart_items | Композиции и количества в корзинах покупателей |
| orders | Заказы, контакты получателя, сумма и текущий статус |
| order_items | Снимки состава и стоимости купленных композиций |
| order_statuses | Справочник статусов |
| order_status_transitions | Разрешённые переходы между статусами для ролей |
| order_status_history | Журнал создания и изменения статусов заказов |
| sessions | Серверные сессии — служебная таблица |
| schema_migrations | Применённые шаги изменения схемы — служебная таблица |

Категории, роли и статусы связаны внешними ключами. Базовые ноты атмосферы остаются небольшим упорядоченным JSON-массивом для описания аромата. Исторические снимки в заказах намеренно хранятся отдельно от изменяемого каталога.

## Технологии и защита

HTML, CSS и JavaScript; Node.js 22+ и Express; MySQL 8; явные SQL-запросы через mysql2 без ORM. Модули сервера используют CommonJS.

Пароли хешируются bcrypt. Сессии хранятся на сервере; cookie использует HttpOnly и SameSite. Изменяющие запросы защищены CSRF-токеном. Права и принадлежность ресурсов проверяются сервером, запросы используют параметры. Денежные расчёты выполняются в целых копейках.

## Статистика и обмен данными

Период статистики определяется датой оформления заказа и включает обе выбранные даты. Сумма и рейтинг учитывают только заказы с текущим статусом «Завершён». Отчёт CSV содержит те же показатели, что и панель, и открывается в Excel. Это сумма завершённых заказов, а не учёт реальных платёжных операций.

JSON содержит атмосферы, ноты, флаконы и совместимость, включая скрытые позиции. Импорт добавляет новые записи и обновляет существующие по коду; совместимость атмосфер из файла заменяется. Отсутствующие в файле позиции сохраняются. Ошибка откатывает весь импорт. Данные аккаунтов и заказов в файл не входят. Лимит — 1 МБ и 200 позиций каждого вида.

## Готовность

Согласованный функционал учебного магазина реализован. Проверены установка схемы на новой MySQL, обновление существующей базы с сохранением данных, основные сценарии покупателя и администратора, ограничения доступа, статистика и обмен каталогом. Приложение рассчитано на локальный запуск; публикация и настройка производственного сервера в этот этап не входят.

Онлайн-оплата, доставка, рассылки, промокоды, многоязычность, несколько валют и склад парфюмерного сырья в объём проекта не входят.
